The study's answer (read this first)

Six stacks, one corpus, one 59-query golden set, one new technique per cycle. The question was never "can this be built" but which technique earns its cost, for which question type, and by how much.

1 — Hybrid search has a cost nobody quotes. BM25+RRF wins where the query carries distinctive tokens (a domain abbreviation, a literal number, a name) and loses where it does not: "which club won…" floods the top-10 with eighteen interchangeable table rows and pushes the answering row out. The semantic regression it causes was fully repaid by the reranker — after which the ablation showed the fusion had become dead weight.

2 — Contextual retrieval: six hours of compute for a delta of zero. A clean negative result, published rather than buried. Two caveats are owed to the technique: these chunks were never truly context-less, and the context generator was a 1.5B model.

3 — From cycle 3 on, the generator is the bottleneck, not retrieval. Retrieval kept improving (R@5 0.60→0.67, MRR 0.52→0.63) while end-to-end number-hit sat at 0.78 and the misses merely relocated between queries at temperature 0. That measurement, not fatigue, is why cycles 6 and 7 were declined.

Full synthesis, including which findings should transfer to another corpus and which should not: see the closing section of results.md.

Limitations (read before trusting any single number)

The golden set was written and annotated by the same AI that built the pipelines. eval/SCHEMA.md planned a 20% human review sample; the sample was generated (eval/REVIEW_SAMPLE.md) but the human review was never done. The honest figure is zero percent independently reviewed — query selection and ground-truth passages may carry the annotator's bias. The stats-based ground truth was extracted programmatically and is not affected.

Judge validation is thin — the faithfulness numbers are the softest in this report. The local judge (llama3.1:8b) is stable under test–retest (agreement 1.00, n=10) but agreed with a manual re-check on only 7 of 13 cases strictly (10/13 under the honest-refusal reading), and that re-check was done by Claude, not a human. Known errors run in both directions: honest refusals scored unsupported, and answers that twisted the context scored supported. Treat "Faithful strict" / "Honest" as indicative aggregates only; the deterministic number-hit metric is the only judge-free answer-quality signal here, and it is what the cycle verdicts lean on.

Small samples. n = 13–18 per question type — one query can move a metric by 7–8 points. Every claim is "deutet auf", not "beweist".

A metric bug shipped, was visible for weeks, and is now fixed. nDCG@10 could exceed its 1.0 bound (cycle 4's semantic aggregate read 1.02) because DCG credited every rank that covered a ground-truth entry without deduplicating entries a higher rank had already covered. Fixed on 2026-09-20 in eval_metrics.py with three regression tests. Re-running every retrieval eval against the unchanged indexes is in progress: cycle(s) 1, 2, 3, 4, 5 still carry pre-fix nDCG@10 values and are marked with a warning sign in results.md's nDCG table. No other metric is affected, and no re-indexing is involved — the re-runs only re-query existing indexes. Scope correction: the earlier write-up claimed Precision@5 was "presumably similarly biased" — it was not. Precision@k is item-wise by definition and needs no ground-truth dedup; only DCG was ever affected, and recall@k and MRR never were.

One corpus, one language, one domain. 955k tokens of German football writing (72% from a single prose source) plus tables and self-rendered stat sheets. The finding least likely to transfer is "the fusion adds nothing once a reranker is present" — that is corpus-size dependent.

CPU-only latency. The reranker's 29.6s/query is honest for this machine and misleading for any machine with a GPU, where it is sub-second. Relative ordering transfers; absolute numbers do not.

Cycle 5 has no technique verdict. See below.

Cycle 5: Visual retrieval (ColQwen2) — attempted, root-caused, closed

The intended showpiece: retrieve stat-sheet images directly via late interaction, no OCR, no chunking. It was built, the 84-page index was computed (~8.2h CPU at ~350s/page), and both the retrieval eval (59 queries) and the VLM generation (13 visual queries) actually ran. Every number in the tables above for cycle 5 comes from those runs.

The result measured a broken model, not the technique. Recall@5 on the visual subset came out at 0.15 (2 of 13), 0 of 13 at rank 1. Inspecting the loaded state dict showed why: the ColQwen2 checkpoint (vidore/colqwen2-v1.0) loads with its language backbone's embedding and final-norm layers randomly initialized — language_model.norm.weight at exactly mean 1.0 / std 0.0 (untouched default init) and embed_tokens.weight at the textbook default std of 0.0200, while the checkpoint's model.* keys are reported as unexpected. Worse, the same drift drops every LoRA weight of the retrieval fine-tune: 14 tensor families across 28 layers (392 tensors) arrive as MISSING under language_model.layers.* while the checkpoint offers them as model.layers.*. Only custom_text_proj — the projection head outside the backbone — loads correctly, which is why nothing crashes. What ran was an untuned Qwen2-VL backbone with a random embedding table, not ColQwen2. That is a colpali_engine==0.3.16 × transformers==5.10.2 module-naming drift; pip's version ranges do not catch it because it is a runtime key-naming mismatch, not a range violation. Reproduced twice independently, inside and outside the eval harness. The corruption applies to the built index as well as to query-time embedding, so a fix requires a full re-index, not just a re-run. Full evidence — verbatim load reports, measured layer statistics, checkpoint key inspection — is committed in docs/colqwen2-load-evidence.md.

A second, independent blocker: the intended --k 5 generation run crashed immediately because rag.py's NUM_CTX=4096 was sized for text contexts and five images need ~7,900 prompt tokens. The reported end-to-end numbers are from an honest --k 1 fallback, not from the designed setup.

Decision: closed at cycle 4. A fix path exists and is specified (a state-dict key-remapping shim at load time, avoiding a global transformers downgrade that would put the reranker and BGE-M3 at risk), and it was time-capped by the closing plan. The cap governed: cycle 5 is published as "attempted, root-caused to a reproducible tooling incompatibility, closed without a technique verdict", with the state-dict evidence committed. The 0.15 must not be read as "ColQwen2 is weak on football stat sheets." Publishing that would have been the easy and false version of this section.
