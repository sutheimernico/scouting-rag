# Plan: Close the Study — scouting-rag

**Date:** 2026-07-21 · **Status:** awaiting go · **Executor:** any capable agent (self-contained — no session context required)

## Context (verified 2026-07-21 by code review)

scouting-rag is a cycle-gated RAG comparison study (Cycles −1…5) on football-scouting documents: judge-free IR metrics against chunking-agnostic ground truth, one variable per cycle, bootstrap CIs, ADR-documented skips of Cycles 6/7. Verdicts: dense baseline keep, hybrid keep-conditionally, **reranking = recommended stack**, contextual retrieval drop (~6h CPU for zero delta), Cycle 5 (ColQwen2 visual) **inconclusive** due to a root-caused dependency bug. 88/88 tests green (16.4s), main clean and pushed.

Three findings change the cost/benefit math that has kept this study open:

1. **The nDCG>1 bug is cheap to fix AND cheap to re-run.** Bug at `src/eval_metrics.py:70-72`: DCG credits gain for every rank whose `covers` set is non-empty without deduplicating already-covered GT indices (recall@k at lines 59-62 does dedup via a `covered` set); IDCG normalizes to `min(n_gt, k)` slots → nDCG up to 1.06. The assumption in `results.md` (lines ~126-129) that a fix requires expensive re-runs is **wrong**: `run_eval.py retrieval` only queries already-built indexes — re-running Cycles 1–4 is minutes, not hours (the 6h figure was Cycle 4's context-generation build, not eval). Verdict impact is plausibly non-zero: reranking promotes semantically similar (= redundant/overlapping) chunks — exactly the bug's trigger — so part of Cycle 3/4's nDCG edge may be artifact. MRR and recall@k are unaffected and independently support the reranking verdict.
2. **`results.md` over-corrects on Precision@5.** It flags precision as "presumably similarly biased" — incorrect: precision@k is item-wise by definition and needs no GT dedup; the code at lines 63-64 is right. The write-up should be corrected, not the code.
3. **ColQwen2 has a clean, low-risk fix path.** Root cause (verified twice via state-dict inspection): `colpali_engine==0.3.16` × `transformers==5.10.2` module-naming drift (`language_model.*` vs `model.*`) leaves the language backbone's `embed_tokens`/`norm` random-initialized. A global transformers downgrade would risk breaking the reranker (`AutoModelForSequenceClassification`) and BGE-M3 in the shared venv — the right fix is a **state-dict key-remapping shim** at load time in `src/visual_index.py:37-52`, verified with the already-built mean/std layer diagnostic. Engineering: a few hours. The dominant cost is unchanged: ~8.2h CPU index build (84 pages × ~350s) + eval — an overnight job.

Also on record (from the study's own docs): golden set was proposed AND annotated by Claude with only a 20% human review sample (`eval/SCHEMA.md`, `eval/REVIEW_SAMPLE.md`); judge validation is thin (7/13 strict agreement, `eval/FAITHFULNESS_SAMPLE.md`) — both transparently documented but under-surfaced in the report. The final synthesis section required by PLAN.md §5 was never written; `results.md` ends mid-decision.

Study principles (do not violate): one variable per cycle; no new cycles (the study's own ADR and Iron Principle reject query-rewriting/eval-set-expansion etc. — the core question is answered); hedged language at small n; every number in report/results traces to a committed eval artifact.
